## 1. Профиль продукта

**NetCert** — бесплатная open-source платформа для подготовки сетевых инженеров к сертификационным экзаменам **Juniper (JNCIA → JNCIE)** и **Cisco (CCNA → CCIE)**.

> Не путать с PKI/TLS-сертификатами. Речь идёт о профессиональной сетевой сертификации вендоров.

**Что внутри (реализовано в коде):**
- Банк вопросов (~9 150 активных после чистки миграцией 063)
- Тайм-симуляция экзаменов с попытками и историей
- Несколько типов вопросов: single / multiple choice, fill-blank, топология/диаграммы, simlet (CLI-сценарии)
- «Deep Dive» объяснения с версионированием (TL;DR, сценарий, почему верно, разбор дистракторов, CLI-примеры, нюансы вендора)
- Live CLI-песочницы через WebSocket: Alpine, FRRouting (VTYSH), cRPD (Junos CLI)
- Лабораторные: микро-лабы (теория), эмуляция на Containerlab (cRPD/FRR), full exam labs
- Quick Labs — облегчённые направляемые лабы
- Интерактивный просмотр топологии на React Flow
- Дашборд с аналитикой готовности
- Материалы для изучения (cheat-sheets, конфиг-гайды)
- Геймификация: streaks, XP, достижения
- i18n EN/RU

**Дисклеймер в футере** (`frontend/lib/i18n/locales/{en,ru}.ts:54`):
> «NetCert — Certification Preparation Platform. Not affiliated with Juniper Networks or Cisco Systems.»

## 3. Оценка по 8 категориям

Легенда: 🟢 хорошо · 🟡 средне/есть риски · 🔴 проблема

### 3.1 Ценностное предложение — 🟡

Реальная боль рынка подтверждена: дорогие экзамены, нехватка легальных качественных тренажёров, особенно для JNCIE-лаб (8 часов). USP заявлены сильные, но **часть не соответствует реализации** (см. §4). Сильная сторона: единственный в OSS движок JNCIE-лабов на Containerlab.

### 3.2 Бизнес-модель — 🔴 (осознанный выбор: Free OSS)

В коде и конфигах **нет ни одного платёжного канала** (grep по `stripe/billing/subscription/payment/license/commercial` — 0 совпадений). Лендинг硬кодит «Free forever» / «Навсегда бесплатно» (`en.ts:27`, `ru.ts:27`).

**Внутреннее противоречие:** восстановленный `CLAUDE.md` фиксирует «никаких подписок и триалов», а `PLAN.md` §18.8.3 вводит Premium $29/мес + Enterprise (только для compute-тяжёлых лаб). По решению владельца **закрепляем модель Free OSS** — план развития (см. `ROADMAP_DEV.md`) строится без монетизации. `PLAN.md` §18.8.3 при этом считается устаревшим и должен быть отмечен как superseded.

### 3.3 Рынок — 🟢

Крупный, растущий, с чётким тех-триггером (регулярный пересертификации Juniper/Cisco).

### 3.4 Конкуренты — 🔴

В коде/docs **ни разу не упомянуты** (grep по `competitor/alternative/unlike/vs.` — 0). Фактическое поле:
- **Boson** (ExSim-Max), **INE**, **CBT Nuggets**, **Pearson / MeasureUp** — платные, dominant в англоязычном сегменте
- **PNETLAB / EVE-NG community** — бесплатные эмуляторы, но без контента и автогрейдинга
- Braindump-сайты — конкуренты по объёму, но нелегальные (NetCert против них — премиум-позиционирование «оригинальный контент без NDA»)

Манифест differentiated позиционирования отсутствует.

### 3.5 Traction — 🔴

**Доказательств реального использования нет:**
- Нет product-аналитики (posthog/amplitude/plausible/mixpanel/sentry — 0 совпадений в коде)
- Нет признаков продакшн-деплоя (только `docker-compose.staging.yml` с localhost-именами, без TLS/домена/reverse-proxy)
- Репо: 14 коммитов, 1 автор, активность 2026-06-10 → 2026-06-23 (~2 недели)
- «Telemetry» в коде — только внутренняя (просмотры объяснений), не агрегированная

### 3.6 Юридическая чистота — 🔴 (высший приоритет)

1. **Нет LICENSE-файла** ни в рабочем дереве, ни в истории git — при заявках «open-source». Без лицензии код по умолчанию **«all rights reserved»**, и никто формально не может его использовать/форкать/вкладывать.
2. **Активное использование товарных знаков** Juniper/Cisco: JNCIA, JNCIE, CCNA, CCIE, ссылки на proprietary-образы cRPD (распространяется Juniper после acquiring лицензии).
3. Дисклеймер «Not affiliated» — необходимый, но не достаточный; fair use для ТМ в образовательном контексте обычно соблюдается, но требует юридического ревью.

### 3.7 Команда и сообщество — 🔴

- **Bus factor = 1.** Один автор, одна ветка, нет контрибьюторов.
- Нет `CONTRIBUTING.md`, `CODE_OF_CONDUCT`, issue/PR-templates, `.github/`.
- Нет каналов сообщества (Discord/Telegram/Slack — 0 упоминаний).
- История коммитов неинформативна: почти все сообщения «update», без семантики (Conventional Commits не используется).
- Аудит-артефакты и PLAN/CLAUDE намеренно gitignored — это разумно для приватного планирования, но снижает прозрачность для потенциальных контрибьюторов.

### 3.8 Контент — 🟡

**Количественно силён:** ~9 150 вопросов, 11 экзаменов, 5 микро-лаб. Но:
- Качество **не публично аудировано** (аудит-скрипт `scripts/audit/` есть, но результаты в gitignored `.md`; на диске только `frontend-audit-results.json` — frontend-only). Для exam-prep-продукта **корректность ответов — ключевое обещание**.
- Исторически 320 вопросов были битыми (исправлено миграцией 063), 5 890 имели дубликаты тел.
- Нет процесса экспертного ревью контента.

## 4. 🔴 Критические расхождения «маркетинг vs реальность»

Эти пункты — **репутационный риск №1** для exam-prep-продукта. Для бесплатного OSS они менее фатальны, чем для коммерческого, но подрывают доверие.

| # | Заявление на лендинге | Реальность в коде | Действие |
|---|---|---|---|
| 1 | «AI-powered adaptive testing with spaced repetition (FSRS)» | `exam_usecase.go` `StartAttempt` выбирает вопросы через `math/rand`. FSRS/SM-2 — только пункты roadmap (`README.md:202-203`). | Либо убрать формулировку с лендинга, либо реализовать FSRS в Фазе 3. |
| 2 | «1,200+ Active learners» (`page.tsx`) | Нет аналитики, нет прод-деплоя. Скорее всего **недоказуемо/выдумано**. | Убрать до появления реальных данных (или заменить на «Self-hostable»). |
| 3 | «9,150+ Questions» (`page.tsx`) vs «1,200+ original questions» (`en.ts:40`) | Два противоречащих числа в одном продукте. | Привести к одному источнику правды (число из БД). |
| 4 | Лендинг упоминает 7 треков | Контент реально есть для 4 экзаменов (200-301, JN0-106, JN0-649, JN0-663) — см. `AGENTS.md`. | Уточнить «available now» vs «roadmap». |

## 5. Бизнес-модель: Free / OSS — обоснование и устойчивость

### 5.1 Почему это валидный выбор

- Сетевая сертификация — область с сильным сообществом и культурой обмена знаниями (ср. успех GNS3, EVE-NG community-версий, Containerlab).
- Бесплатный контент + self-hostable создаёт **распространение через энтузиастов и учебные центры**, что builds moat лучше, чем подписка в русскоязычном сегменте с низкой готовностью платить в USD.
- Снимает значительную часть юридических рисков монетизации чужих ТМ (не продаём чужое).

### 5.2 Пути устойчивости без монетизации

| Источник | Механика | Риски/ограничения |
|---|---|---|
| GitHub Sponsors / Open Collective / Boosty / Patreon | Добровольные спонсорства от пользователей и компаний | Непредсказуемый поток; в RU-сегменте слабо развито |
| Гранты (NGI / Sovereign Tech Fund / NLnet) | Финансирование public-code проектов | Требует заявочной работы; не вечный источник |
| B2B-деплой без SaaS | Компании платят за **интеграцию/поддержку/кастомизацию**, а не за лицензию | Требует SLA-инфраструктуры; размывает «free»-нарратив, если не позиционировать аккуратно |
| Партнёрство с учебными центрами | Бесплатный инструмент в их программах → рефлексивное спонсорство/вклад контентом | Зависит от готовности вендоров |
| Контент-контрибуции сообщества | Снижение нагрузки на одного автора — главный «социальный капитал» | Требует гайдлайнов и ревью-процесса |

### 5.3 Ограничения Free-модели (фиксируем честно)

- **Тяжёлые лабы убыточны в compute.** JNCIE 8-часовая лаб на cRPD/vQFX/vSRX = десятки GB RAM на сессию. Без платного тира либо (а) ограничивать concurrency и предлагать self-host, либо (б) искать гранты на инфраструктуру, либо (в) сделать лабы «run-on-your-own-machine» с понятным гайдом.
- **Bus factor = 1** сохраняется, пока нет комьюнити. Это **главный стратегический риск** проекта — не технический, а организационный.
- **Нет KPI для оценки успеха.** Без аналитики нельзя доказать спонсорам/грантодателям охват.

1. **Добавить LICENSE.** Рекомендация: **AGPL-3.0** (защищает от закрытого SaaS-риза без отдачи изменений) или **MIT** (максимальная свобода Adoption). Для «free forever»-модели AGPL-3.0 лучше выравнен с ценностями.

## 7. Резюме

NetCert — **амбициозный, технически добротный (Go Clean Architecture + Next.js), но очень молодой (2 недели, 1 автор) free/OSS-проект** для подготовки сетевиков к Juniper/Cisco-сертификации, с акцентом на русскоязычный сегмент. Реализованные фичи (банк вопросов, симуляция, объяснения, live CLI-песочницы, Containerlab-лабы) — действительно полезны и конкурентоспособны.

**Ключевые бизнес-риски:**
1. Нет LICENSE при заявках «open-source» — блокирует весь OSS-нарратив.
2. Маркетинг-заявления (FSRS, «1 200+ learners») не подтверждены кодом.
3. Bus factor = 1 — без комьюнити проект уязвим к одному автору.
4. Тяжёлые лабы требуют стратегического решения в free-модели (self-host vs ограниченный concurrency vs гранты).

**Ключевая стратегическая рекомендация:** приоритет — не фичи, а **доверие и комьюнити**: лицензия, честная статистика, прозрачность аудитов, каналы для вклада. Технический параллельный трек — закрытие критических уязвимостей (см. `AUDIT_TECHNICAL.md`), без которых публичный деплой опасен.
