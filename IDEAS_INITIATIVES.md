# NetCert — Инициативы развития

**Дата:** 2026-07-17 · **Модель:** Free / OSS навсегда
Инициативы сгруппированы по направлениям. Каждая помечена усилием (S/M/L) и зависимостями от фаз `ROADMAP_DEV.md`.

> Эти идеи **не являются обязательными** для минимального релиза (Фаза 0 + Фаза 1). Они описывают ростовой потенциал после того, как фундамент качества и безопасности заложен.

---

## 1. Технические инициативы

### 1.1 AI-генерация и семантика объяснений [L] — *из PLAN.md §17 V2*
- LLM (Claude через litellm) для черновиков объяснений по JSONB-схеме (`tl_dr`, `scenario`, `why_correct`, `distractor_analysis`, `cli_examples`, `vendor_nuances`).
- **pgvector** для семантического поиска похожих вопросов и weak-topic кластеризации.
- Контур «AI draft → экспертное ревью → публикация» — не autonomous generation, чтобы не допустить галлюцинаций в exam-prep-контенте (корректность = ключевое обещание).
- Зависимость: Фаза 1 (типизированные ошибки), таблицы `explanation_sections` (уже в схеме PLAN §5).

### 1.2 Геймификация [M]
- XP за завершённые попытки/лабы, streak за ежедневную активность, leaderboard (opt-in).
- Достижения уже частично в коде (`en.ts:126-134`: First Exam, Perfect Score, Study Streak, Jack of All Trades) — нужно подключить таблицы `user_progress` + widget на дашборде.
- Осторожно в free/OSS: leaderboard не должен превращаться в инструмент сравнения, отвлекающий от обучения.

### 1.3 ML-предиктор готовности к экзамену [L] — *из PLAN §16 KPI*
- Модель на истории попыток (точность, время на вопрос, повторные ошибки по blueprint-секциям) → «readiness score».
- Стартовая версия: эвристика/логрег на базе `user_weaknesses`. Полная: градиентный бустинг.
- Визуализация: confidence-interval + «что подтянуть» (ссылки на study-материалы и weak-зоны).

### 1.4 WebAssembly-симулятор Junos/IOS CLI для offline [L]
- Компиляция легковесного CLI-парсера (или yansi-style simulator) в WASM → работает в браузере без Containerlab-инфраструктуры.
- Зона применения: micro-labs уровня JNCIA/CCNA, где не нужен полный routing-stack, только синтаксис и show-output.
- Снижает инфраструктурный барьер (главный pain free-модели) — см. §5.

### 1.5 Observability: OpenTelemetry [M]
- Traces (Tempo), metrics (Prometheus), logs (Loki) — уже заявлены в PLAN §3, но не реализованы.
- Для публичного инстанса это и security (audit trail), и качество (p95 latency, lab pod startup time — KPI из PLAN §16).

### 1.6 Server Components / Streaming [M]
- Перевод read-only страниц на RSC (Фаза 2.5) + streaming для тяжёлых списков вопросов → улучшение TTFB и SEO.

## 2. Контентные инициативы

### 2.1 Расширение банка simlet-вопросов [M]
- Simlet (CLI-сценарии с `show`-выводом) — KPI PLAN §16: 10 → 50+.
- Это самое трудоёмкое, но и самое дифференцирующее против braindump-сайтов: реальное понимание vs зубрёжка.

### 2.2 Quick Labs по всем 5 трекам Juniper [M]
- Сейчас micro-labs есть для OSPF/BGP/MPLS/IS-IS/CLI-basics (5 шт.).
- Расширить до покрытия Enterprise / Service Provider / Security / Data Center / Automation — каждый трек 5–8 микро-лаб.

### 2.3 Cisco CCNP ENCOR + CCIE [L]
- Расширение за пределы CCNA. CCIE EI 8-hour lab — флагман, но compute-тяжёлый (см. §5).

### 2.4 Публичный отчёт качества контента [S]
- Облегчённая версия `AUDIT_QUESTIONS_LABS.md` без раскрытия ответов: число вопросов, покрытие blueprint, % прошедших ревью.
- Доверие для exam-prep-продукта = конверсия (даже в free: в регистрацию и вклад).

### 2.5 Community-contributed questions [M]
- Процесс: contributor → JSON-схема (как в `CLAUDE.md` Role 2) → CI-валидатор → экспертное ревью → миграция.
- Снижает bus factor=1 по контенту.

## 3. Сообщество и распространение

### 3.1 Telegram-канал/группа [S]
- Естественно для RU-сегмента. Объявления релизов, разборы вопросов, feedback.

### 3.2 Еженедельные разборы [M]
- Короткий контент: «разбор одного BGP-вопроса», «типичная ошибка в OSPF». Works as content-marketing без бюджета.

### 3.3 Contributor program [M]
- Документированный путь: от первого issue до maintainer. CONTRIBUTING + «good first issue»-лейблы.
- Признание контрибьюторов (README-credits, badges).

### 3.4 Wiki / Knowledge Base [M]
- Public wiki по объяснениям и технологиям — двойное использование: study-material + SEO-трафик.

### 3.5 Integration с GNS3/EVE-NG/PNETLAB [M]
- Экспорт NetCert-топологий в формат этих популярных эмуляторов → user может крутить lab locally.
- Снимает инфраструктурную нагрузку с публичного инстанса.

## 5. Стратегия compute-тяжёлых лаб (главная проблема free-модели)

JNCIE/CCIE 8-hour лаб = десятки GB RAM/сессию. В free-модели без платного тира варианты:

| Подход | Плюс | Минус |
|---|---|---|
| **Self-host-first** | Ноль compute-расходов на нас; user крутит у себя | Требует Juniper cRPD-лицензию + Docker-мощность у user |
| **Ограниченный concurrency** на публичном инстансе | Демо-доступ для всех | Queue/фрустрация при пике |
| **Гранты на инфру** (NLnet/NGI/Sovereign Tech) | Покрытие расходов без монетизации users | Заявочная работа, не бесконечно |
| **WASM-симулятор** (инициатива 1.4) | Полностью в браузере, ноль server-compute | Ограничен сложностью эмулируемых сценариев |
| **Экспорт в GNS3/EVE-NG** (3.5) | User использует свою инфру |UX-разрыв |

**Рекомендация:** комбинировать self-host-first (для серьёзных лаб) + WASM/micro-labs (для JNCIA/CCNA уровня) + ограниченный демо-concurrency на публичном инстансе. Это держит модель free, не требуя подписок.

## 6. Риски и митигации

### 6.1 Юридические
| Риск | Вероятность · Impact | Митигация |
|---|---|---|
| ТМ Juniper/Cisco (JNCIA, CCNA…) | Low · Medium | Fair use в образовательном контексте; дисклеймер уже есть; юрист-ревью перед масштабом; опционально партнёрство 4.1 |
| NDA-контент (реальные вопросы экзаменов) | Medium · Critical | 100% оригинальные вопросы из публичных blueprint; `content_hash` audit trail; запрет braindump-контрибуций в CONTRIBUTING |
| Отсутствие LICENSE | High · High | Фаза 4.1 — добавить LICENSE (AGPL-3.0 рекомендован для free-модели) |

### 6.2 Технические
| Риск | Митигация |
|---|---|
| Containerlab pod fails to start | Graceful degradation к «теоретической лабе» (из PLAN §15); healthcheck + retry; observability 1.5 |
| Postgres degradation на миллионах attempt_answers | Партиционирование + S3 archival (из PLAN §15) |
| Lab Orchestrator SPOF | Horizontal scaling, идемпотентные операции |

### 6.3 Организационные
| Риск | Митигация |
|---|---|
| **Bus factor = 1** (главный риск) | Сообщество (§3), контрибьютор-program (3.3), документация, пара maintainer'ов |
| Выгорание автора | Реалистичный темп roadmap; community接管 контента |
| Техдолг накапливается быстрее фич | Дисциплина: Фаза 1 (CI/линтеры/тесты) как обязательный gate перед Фазой 3 |

## Резюме

Главный рычаг развития NetCert в free/OSS-модели — **не фичи, а сообщество и доверие**. Технические инициативы (FSRS, AI-объяснения, WASM-симулятор) усиливают продукт, но без (а) критической массы контрибьюторов и (б) доказанной корректности контента проект останется уязвимым к bus factor=1. Поэтому параллельно с техническим roadmap'ом (`ROADMAP_DEV.md`) community-инициативы (§3) — стратегический приоритет №1 после закрытия security-блокеров Фазы 0.
